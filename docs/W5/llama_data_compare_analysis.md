## 2. 输入长度对 TPOT 的影响

**c=1（单请求）：输入长度几乎无影响**

```
128in:  P50=12.98  P90=13.58  P99=15.18
512in:  P50=12.72  P90=12.86  P99=30.01 ← 异常值
1024in: P50=12.74  P90=12.82  P99=30.62 ← 异常值
```

P50 差异 <2%，在噪声范围内。瓶颈是读取模型权重，不是计算 attention。1024 token 比 128 token 多 8× 计算量，但在 decode 阶段每步都要重新读取所有权重（7B × Q4 = 3.5GB），读权重的时间 >> 多出来那点 attention 计算。

**512/1024in P99 异常**：各有 1 次慢请求（30.01ms / 30.62ms），远超正常 P90（12.86ms）。可能原因：CUDA graph 重编译或 GPU 频率瞬时切换，不影响总体结论。

**c=16（高并发）：1024in 明显恶化**

| c | 128in/64out P50 | 1024in/64out P50 | 比率 |
|---|----------|-----------|------|
| 1 | 12.98 | 12.74 | 0.98× |
| 4 | 38.15 | 61.92 | 1.62× |
| 8 | 75.61 | 125.03 | 1.65× |
| 16 | 146.39 | 224.02 | 1.53× |

1024in 的 KV cache 是 128in 的 8×（56MB vs 7MB per sequence）。c=16 时 16 条 1024-token sequence 约 896MB KV cache 争抢显存带宽。llama.cpp 的连续 KV cache 方案在高并发长上下文时暴露带宽瓶颈。

---

## 3. 输出长度对 TPOT 的影响

**TPOT 与输出长度无关，per-token 时间是常数**

```
128in/64out  c=1: P50=12.98  P90=13.58
128in/256out c=1: P50=12.75  P90=12.80
```

输出从 64 变到 256 token，TPOT 几乎不变。decode 阶段每生成一个 token 的计算量相同（扫描全量历史 KV + 读一遍权重 + softmax），不因目标长度改变。

## 4. 并发扩展与 KV Cache 瓶颈

**128in/256out 扩展相对均匀**

| c | P50 | P90 | P99 | P50→P99 差距 |
|---|-----|-----|-----|-------------|
| 1 | 12.75 | 12.80 | 13.70 | +7.5% |
| 4 | 31.64 | 31.87 | 31.89 | +0.8% |
| 8 | 63.34 | 64.00 | 64.15 | +1.3% |
| 16 | 119.33 | 124.64 | 124.73 | +4.5% |

调度均匀，P50 和 P99 差距小（<8%），无严重排队现象。

**1024in/256out 长尾明显恶化**

| c | P50 | P90 | P99 | P50→P99 差距 |
|---|-----|-----|-----|-------------|
| 1 | 12.70 | 12.75 | 13.25 | +4.3% |
| 4 | 41.24 | 41.71 | 41.82 | +1.4% |
| 8 | 82.67 | 83.03 | 83.10 | +0.5% |
| 16 | 153.11 | 166.92 | 167.00 | **+9.1%** |

长请求不仅 P50 更高（1024in 比 128in 高出 1.5-1.6×，见第 2 节），P50→P99 差距也更大（9.1% vs 4.5%）。KV cache 抢占显存带宽导致抖动加剧。

## 5. 异常数据说明

| 组 | P50 | P90 | P99 | 问题 |
|----|-----|-----|-----|------|
| 512in/64out c=1 | 12.72 | 12.86 | **30.01** | P99 跳 2.5× |
| 1024in/64out c=1 | 12.74 | 12.82 | **30.62** | P99 跳 2.5× |

各有 1 个慢请求拉高 P99。正常 P99 应与 P90 接近（如 128in/64out: P90=13.58, P99=15.18, +11%），而这两组 P99 暴增至 30ms。可能原因：CUDA graph 首次编译或 GPU 频率/P-state 切换。属于个别抖动，不影响整体趋势。

## 附录：与 vLLM GPTQ 方向性对比

> 不同 GPU 不可直接对比，仅供方向性参考

| 引擎 | 模型 | GPU | c=1 TPOT | c=max 并发 | 增幅 |
|------|------|-----|---------|----------|------|
| vLLM | GPTQ-Int4 | RTX 4090D | 6.18ms | 8.69ms @c=30 | +41% |
| llama.cpp | Q4_K_M | RTX 5060 | 12.75ms | 119ms @c=16 | +9.4× |

vLLM PagedAttention: block 共享 → 多 sequence KV cache 高效复用显存带宽 → 30 并发仅 +41%
llama.cpp: 连续 KV cache → 每个请求独占一块 → 高并发长上下文抢带宽 → c=16 时 +9.4×

**核心差异**：PagedAttention 的 block 切分 + 按需分配，让 KV cache 在不同请求间共享物理显存，减少争抢。llama.cpp 为单请求预分配连续空间，在并发场景下带宽瓶颈明显。
