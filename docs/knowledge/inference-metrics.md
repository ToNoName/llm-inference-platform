# 推理性能指标

> TTFT 是"用户等多久看到第一个字"，TPOT 是"每个字出来多快"。生产用 P50/P90/P99，不用平均值。

---

## 1. TTFT：Time To First Token

**定义**：请求发出到第一个 token 返回的时间。

```
Client ──[网络]──→ Server (Prefill: 全量计算 prompt KV)
                    → 生成第一个 token
Client ←──[网络]──  收到第一个 token
└────────── TTFT ──────────┘
```

**包含什么**：
- 网络传输请求
- vLLM prefill 阶段（prompt 全量 attention 计算 + KV 填入）
- 第一个 decode token 生成
- 网络回传

**对用户意味着**：**等多久才开始看到回复**。TTFT 大 = 用户感觉"卡了"。

**影响因素**：输入长度（越长 prefill 越久）、网络延迟、GPU 忙闲程度。

---

## 2. TPOT：Time Per Output Token

**定义**：生成阶段，每个 output token 平均花的时间。

```
TPOT = backend_latency / output_tokens
```

**包含什么**：
- Decode 一步：读全部历史 KV + 读权重 + attention + FFN + softmax
- 网络

**对用户意味着**：**回复的字闪现速度**。TPOT 大 = 一个字一个字慢慢蹦。

**影响因素**：模型大小（权重读取量）、并发数（KV cache 争抢带宽）、量化级别。

**TPOT 是常数**：每 token 计算量完全相同，不受输出总长度影响。

---

## 3. P50 / P90 / P99：百分位

为什么不用平均值？**平均值被慢请求拉高，看不到抖动。**

```
30 个请求的 TPOT，排序：
第 1 个（最快）：109ms
第 15 个：       119ms  ← P50（一半用户比这快）
第 27 个：       125ms  ← P90（90% 用户比这快）
第 30 个（最慢）：167ms  ← P99（99% 用户比这快）

P50→P99 差距 = 167 - 119 = 48ms → 抖动 40%
```

| 指标 | 含义 | 数据要求 |
|------|------|---------|
| P50 | 典型用户体验 | ≥5 样本 |
| P90 | 大多数用户的体验 | ≥5 样本 |
| P99 | 长尾最差体验 | ≥30 样本 |

**为什么盯 P99**：如果每天 10 万次请求，P99=500ms 意味着 1000 个用户每天等半秒以上。投诉率 = P99 以下的那批人。

---

## 4. SLO 设计

```
SLO：99% 的请求 TPOT < 150ms, 99.9% 的请求 TPOT < 300ms
```

**如何确定 SLO 值**：
1. 跑压测矩阵，拿到各并发下的 P50/P90/P99
2. P90 作为目标值（允许 10% 的波动）
3. P99 作为告警阈值（超过说明系统有问题）
4. 生产监控：Prometheus histogram 分桶统计，按小时报 P99

---

## 5. 与用户体验的对应

```
用户发消息 ──TTFT=1500ms──→ 看到第一个字
                               │
                    TPOT=12ms/字
                               │
                               ↓
                         字一个字一个字蹦出来
```

| 体验 | TTFT | TPOT |
|------|------|------|
| 秒回 | <500ms | <10ms |
| 可接受 | 500-2000ms | 10-20ms |
| 需要优化 | >2000ms | >20ms |

---

## 6. 面试一句

> "TTFT 衡量 prefill 速度，TPOT 衡量 decode 速度。生产盯 P99 而非平均值，因为平均值抹平了长尾抖动。压测 n≥30 才能信 P99，P50/P90/n≥5 即可。"
