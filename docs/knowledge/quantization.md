# 量化：GPTQ / AWQ / GGUF

> 量化把 FP16 权重压缩到 INT4/INT8，减少显存和带宽。GPTQ 适合 GPU 在线推理，GGUF 灵活适合边缘部署，AWQ 重量化激活保护重要通道。

---

## 1. 为什么量化

```
FP16: 14.5GB 模型 + KV cache → OOM on 8GB
INT4: 3.5GB 模型 + KV cache → 8GB 能跑
```

**加速原理**：权重减少 4× → 每步读取数据量减少 4× → TPOT 降 ≈ 2.5×（实际受 dequant 开销限制）。

---

## 2. GPTQ vs AWQ vs GGUF

| | GPTQ | AWQ | GGUF |
|---|------|-----|------|
| 原理 | 逐层最小化量化误差 | 保护重要激活通道 | 灵活量化 + 混合精度 |
| 引擎 | vLLM 原生支持 | vLLM 支持 | llama.cpp 专用 |
| 加速比 | ~2.5× vs FP16 | ~2.6× vs FP16 | ~2-3× vs FP16 |
| 显存 (7B) | 5.3GB | 5.3GB | 4.5GB (Q4_K_M) |
| 适用 | 生产 GPU 推理 | 追求更高精度 | 低显存 / CPU 推理 |

> 数据来自 W2/W4 实验：Qwen2.5-7B GPTQ-Int4 TPOT=6.18ms vs FP16=15.56ms，加速 2.52×（RTX 4090D）。

---

## 3. GGUF 量化级别

| 级别 | 大小 (7B) | 质量 | 适用 |
|------|----------|------|------|
| Q2_K | 2.8GB | 有损较多 | 极限压缩 |
| Q4_K_M | 4.5GB | 轻微下降 | **推荐平衡点** |
| Q8_0 | 7.7GB | 几乎无损 | 不差显存时 |

---

## 4. 面试一句

> "量化本质是牺牲极少精度换显存和带宽。GPTQ/AWQ 适合 vLLM 生产部署，GGUF 适合 llama.cpp 在受限硬件上灵活选型。Qwen2.5-7B GPTQ-Int4 比 FP16 快 2.5×，显存省 9GB。"
